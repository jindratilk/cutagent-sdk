# Fusion 3D scenes

Build a 3D branch as scene data, render it to an image, then composite that image with ordinary 2D nodes:

```text
geometry + camera → Merge3D → Renderer3D → Merge → MediaOut
```

`Merge3D` combines objects by their position in 3D space; it has no 2D foreground/background order. A camera is another scene object, so merge it with the geometry before rendering. `Renderer3D` is the boundary that converts the scene to a 2D image. Put screen-space graphics or footage composites after that boundary.

Use [graph basics](./graph-basics.md) for builder rules and complete-graph replacement. Use [coordinates and time](./coordinates-and-time.md) before mixing Fusion-frame animation with timeline positions.

## Build the supported typed scene

The current typed registry exposes a small 3D foundation: `Shape3D`, `Camera3D`, `Merge3D`, and `Renderer3D`. This runner module selects one durable holder item, replaces its one Fusion composition with a structurally valid 3D branch, and requires the SDK's structural verification:

```js
export default async function ({ sdk, timeline, snapshot, progress }) {
  const candidates = snapshot.videoTrack(2).clips.filter(
    (clip) => clip.name === "3D Holder",
  );
  if (candidates.length !== 1 || candidates[0].id === null) {
    throw new Error(`Expected one durable 3D Holder on V2; found ${candidates.length}`);
  }

  const compositions = await timeline.fusion.forTimelineItem(
    candidates[0].id,
    snapshot.revision,
  );
  const composition = compositions.at(0);
  if (compositions.length !== 1 || !composition) {
    throw new Error(`Expected one Fusion composition; found ${compositions.length}`);
  }

  const graph = sdk.fusionGraph()
    .node("surface", "Background", {
      TopLeftRed: 0.9,
      TopLeftGreen: 0.18,
      TopLeftBlue: 0.04,
      TopLeftAlpha: 1,
    })
    .node("shape", "Shape3D")
    .node("camera", "Camera3D", {
      "Transform3DOp.Translate.Z": 5,
    })
    .node("scene", "Merge3D")
    .node("renderer", "Renderer3D")
    .node("backdrop", "Background", {
      TopLeftRed: 0.025,
      TopLeftGreen: 0.035,
      TopLeftBlue: 0.06,
      TopLeftAlpha: 1,
    })
    .node("composite", "Merge")
    .node("output", "MediaOut")
    .connect("surface", "Output", "shape", "MaterialInput")
    .connect("shape", "Output", "scene", "SceneInput1")
    .connect("camera", "Output", "scene", "SceneInput2")
    .connect("scene", "Output", "renderer", "SceneInput")
    .connect("backdrop", "Output", "composite", "Background")
    .connect("renderer", "Output", "composite", "Foreground")
    .connect("composite", "Output", "output", "Input")
    .output("output")
    .compile();

  const impact = composition.previewApply(graph);
  console.log({
    target: impact.target,
    intendedEffects: impact.intendedEffects,
    protectedState: impact.protectedState,
  });

  progress("Replacing the exact Fusion composition with a 3D scene");
  const operation = await composition.applyGraph(graph, {
    precondition: composition.revision,
    idempotencyKey: sdk.idempotencyKey(),
  });
  const terminal = await operation.wait();

  if (terminal.status !== "succeeded") {
    console.error({
      status: terminal.status,
      failure: terminal.failure,
      result: "result" in terminal ? terminal.result : undefined,
      recovery: "recovery" in terminal ? terminal.recovery : undefined,
    });
    throw new Error(`Fusion 3D graph ended as ${terminal.status}`);
  }
  if (
    terminal.verification.outcome !== "passed" ||
    terminal.result.protectedStatePreserved !== true ||
    terminal.result.readback.graphDigest !== terminal.result.appliedGraphDigest
  ) {
    throw new Error("Fusion 3D structural verification did not pass");
  }

  console.log({
    operationId: operation.operationId,
    readback: terminal.result.readback,
    renderedReview: terminal.result.renderedReview,
    temporalReview: terminal.result.temporalReview,
  });
}
```

Run it only after confirming that replacing the complete holder composition is intended:

```sh
cutagent-sdk --title "Build the 3D holder scene" scene-3d.mjs
```

The first `Background` supplies a bright opaque material to the `Shape3D`; the second supplies a dark opaque 2D backdrop after rendering. Keeping those roles separate makes the 3D-to-2D boundary explicit.

Do not leave the camera and shape together at the origin. Fusion's camera looks along its negative Z-axis, so this example places the camera at Z = 5 and leaves the shape at Z = 0, five units in front of it. The manual notes that camera-space Z values become more negative farther from the camera. Adaptive near/far clipping is enabled by default for a perspective camera; if you disable it in a richer scene, keep the geometry between the explicit near and far planes.

The registry contains `Renderer3D.CameraSelector`, but it is a `FuID`, which the current typed builder cannot set as a literal. This graph therefore includes exactly one camera: `Renderer3D` finds that camera in the merged scene, as DaVinci Resolve documents. Do not add a second camera until the public SDK can select one explicitly or you move the scene to a reviewed settings/scripting workflow. Use only exact input IDs found in `sdk.FUSION_REGISTRY`; do not translate Inspector labels into guessed property names.

## Decide where a transform belongs

- Transform a geometry node when only that object should move.
- Transform an upstream `Merge3D` when a grouped sub-scene should move together.
- Transform the final `Merge3D` only when the camera, lights, and every included object should share the transform.
- Animate the camera for a viewpoint move; animate geometry for object motion. These are visually different even if the relative displacement is similar.
- Place a screen-space label after `Renderer3D`. A label that must move with an object belongs in the 3D scene and needs supported image-plane or 3D-text geometry.

The current typed registry exposes constant numeric 3D transform inputs but marks no input as proven animatable. Do not cast around `FusionGraphBuilder.animate()`. For current keyframe actions and their composition-frame semantics, read [animation](./animation.md).

## Respect the current boundary

The typed registry is not Fusion's full 3D catalog. It currently omits `ImagePlane3D`, `Text3D`, lights, imported meshes, and material/shader tools. It also has no `MediaIn`, so this builder cannot preserve source footage inside the replacement graph. Use it for a dedicated generator or holder composition whose entire graph may be replaced.

For a richer scene, reuse or author a reviewed `.setting` only through the documented path in [setting files](./setting-files.md), or inspect the exact live surface described in [scripting](./scripting.md). Do not substitute an unregistered node name, guessed port, raw expression, or fabricated composition reference.

Typed compilation proves registered nodes, literal input types, exact observed connection pairs, acyclic output reachability, and registry binding. A successful `applyGraph()` additionally proves structural graph readback and the reported protected state. It does not prove framing, material appearance, occlusion, lighting, alpha, or motion quality: current graph results report visual, semantic, and temporal review as `not_run` unless separate evidence exists.

After a material 3D change, inspect representative frames that reveal the camera view, object placement, clipping, alpha, and the 2D composite. Review multiple frames or a rendered excerpt for any motion. Follow [preview and debugging](./preview-and-debugging.md); a single still cannot prove a camera move or object animation.
